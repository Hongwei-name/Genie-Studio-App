# zero_K-Genie

智元标注审核助手桌面端。它为广西智数智能标注工作场景而生，把任务同步、验收失败 EP 汇总、审核页面打开、运行统计和浏览器脚本集中到一个 Windows 工具中。

> **当前版本：`3.0.7`（最终版本）**
>
> 这是项目最后一次正式发布。原研发成员已经离开原工作岗位，项目将不再继续维护、修复或适配平台变化。请在确认当前平台接口和浏览器环境仍兼容后使用。

## 适用环境与重要说明

- Windows 10/11 64 位。
- 一个可以正常登录智元标注平台的账号。
- Chromium 内核浏览器（推荐 Chrome 或 Edge）。
- 浏览器脚本功能需要安装脚本猫（ScriptCat）扩展。
- 本工具不是智元平台官方软件，只适用于你已经获授权的工作场景。
- 应用会使用账号登录后的 Cookie 请求平台接口。Cookie 只保存在本机配置中，请勿截图、复制或提交到公开仓库。
- 平台接口、登录流程或页面结构变更后，当前版本可能失效；由于项目停止维护，不承诺兼容未来变化。

| 失败 EP | 扫描所有任务中的验收失败 EP，按任务、Job 和状态筛选，集中重新处理 |

| 偏好设置 | 配置 Cookie、刷新频率、并发数、EP 打开方式、初筛人和自动打开 |
| 浏览器脚本 | 安装并配置 zero_K-Genie 审核辅助脚本 |

## 新用户首次使用教程

建议严格按照以下顺序操作：先安装浏览器脚本，再登录获取 Cookie，最后保存配置并检查工作台。

### 1. 安装应用

1. 下载上方的 `zero_K-Genie_Setup_3.0.7.exe`。
2. 双击安装程序，选择安装目录并完成安装。
3. 启动 `zero_K-Genie`，首次启动可能需要等待几秒加载本地资源。

### 2. 安装脚本猫和审核脚本

1. 点击左侧 **偏好设置**。
2. 找到 **浏览器脚本** 区域，点击 **一键安装**。
3. 应用会用系统默认浏览器打开脚本猫官网和 zero_K-Genie 用户脚本安装页。
4. 在脚本猫官网按浏览器提示安装扩展。浏览器的扩展安装必须由用户确认，应用不能静默完成。
5. 在用户脚本页面点击安装或确认按钮。
6. 打开脚本猫的脚本管理页，确认 `zero_K-Genie Review Helper` 已启用。

如果浏览器没有自动打开页面，可以手动访问：

- 脚本猫官网：<https://scriptcat.org/>
- [脚本猫中的 zero_K-Genie 详情页（推荐备用入口）](https://scriptcat.org/zh-CN/script-show-page/7565)
- 用户脚本安装地址：<https://raw.githubusercontent.com/Hongwei-name/Genie-Studio-App/zero/userscripts/zero-K-Genie.user.js>

如果直接打开用户脚本地址显示空白页、下载页或 Tampermonkey 的中转页，请优先打开上面的脚本猫详情页，在脚本猫中点击安装。安装完成后，在脚本猫管理页确认脚本已启用。

### 3. 登录并获取 Cookie

1. 在 **偏好设置 → 认证** 中点击 **点击登录获取 Cookie**。
2. 在弹出的登录页面完成智元平台登录和必要的验证。
3. 登录完成后，应用会自动读取当前页面 Cookie 并关闭登录窗口。
4. 确认 **Token (Cookie)** 输入框已经出现内容。
5. 点击页面底部 **保存配置**。
6. 右上角状态显示 **已认证 · 运行中**，说明认证配置已生效。

如果自动获取失败，可以在浏览器开发者工具中复制当前站点 Cookie，粘贴到 Token 输入框后保存。Cookie 是敏感凭据，只应保存在自己的电脑上。

### 4. 配置刷新和并发

在 **刷新设置** 中：

- **刷新频率**：填写秒数。填写 `0` 可以暂停自动刷新；数值越小，请求越频繁，也越容易触发平台限流。
- **暂停刷新**：临时停止任务同步，恢复后继续使用原来的刷新间隔。

在 **并发与性能** 中：

- **并发数**：可以直接输入任意正整数，也可以使用两侧的加减按钮。建议先使用默认值 `16`，确认账号和网络稳定后再逐步调整。
- 并发越高不一定越快；平台限流、网络质量和任务数量都会影响实际速度。

在 **自动打开** 中：

- **EP 打开方式 → 浏览器**：使用系统浏览器打开审核页，适合配合脚本猫脚本。
- **EP 打开方式 → WebView**：在应用内打开审核页，适合不希望切换浏览器窗口的场景。
- **自动打开新 EP**：只会自动打开符合条件的新 EP，不会自动打开验收失败 EP。

在 **验收失败筛选** 中：

- **初筛人**：填写用户名后，失败 EP 页面只显示对应初筛人的记录；留空则不按初筛人过滤。
- **显示所有 Job**：关闭时只显示有待审核 EP 的 Job，打开时显示全部 Job。

修改完成后务必点击 **保存配置**。

### 5. 验证是否正常工作

1. 点击左侧 **工作台**，等待任务列表完成同步。
2. 展开一个任务，确认 Job 和 EP 数量能够加载。
3. 打开一个待审核 EP，确认审核页面能正常访问，且页面中出现脚本辅助面板。
4. 点击左侧 **数据统计**，确认今日统计、任务负载和最近事件区域能够显示。
5. 点击左侧 **失败 EP**，必要时点击右上角 **重新扫描**，确认扫描进度和结果正常。

## 日常工作流程

### 工作台

工作台按待审核数量展示任务。可以展开任务查看 Job，再展开 Job 查看 EP；使用刷新按钮立即同步，也可以使用批量打开处理多个 EP。右上角的同步状态可以帮助判断当前是否正在加载或已暂停。

### 失败 EP

失败 EP 页面用于集中处理验收失败记录。扫描完成后可以按任务、Job 和状态筛选，点击某条记录的 **处理** 按钮打开对应审核页。页面使用统一滚动区域，长列表可以直接滚动到底部继续加载和操作。

### 数据统计

数据统计页面包括今日完成数量、视频时长、处理进度、任务负载、最近事件和每日谏言。每日谏言来自一言服务；网络不可用时会自动使用本地备用内容，不影响审核功能。

### 运行日志

运行日志用于排查登录失败、接口请求失败、扫描失败和 EP 打开失败。遇到问题时，建议先查看日志中的第一条错误，再检查 Cookie、网络和刷新状态。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 安装后无法启动 | 确认使用 Windows 10/11 64 位，并重新运行安装程序；不要直接移动安装目录中的单个 exe 文件。 |
| 一键安装没有打开浏览器或脚本安装页 | 检查 Windows 默认浏览器设置；也可以直接前往 [脚本猫 zero_K-Genie 详情页](https://scriptcat.org/zh-CN/script-show-page/7565) 安装。 |
| 脚本猫已安装但没有脚本面板 | 在脚本猫管理页启用脚本，确认当前页面是智元平台，再刷新页面。 |
| 登录页面无法获取 Cookie | 确认登录已经完成，等待页面跳转后再关闭；也可以手动复制 Cookie 粘贴到 Token 输入框。 |
| 右上角一直显示未认证 | 确认 Cookie 输入框不为空，点击保存配置；Cookie 失效时需要重新登录获取。 |
| 任务列表为空或同步失败 | 检查网络和 Cookie，确认没有暂停刷新，再查看运行日志。 |
| 扫描失败 EP 很慢 | 降低并发数，检查平台是否限流；任务很多时首次扫描本来就需要更长时间。 |
| 页面打开但没有辅助功能 | 选择“浏览器”打开方式，确认脚本猫和用户脚本均已启用。 |
| 每日谏言无法加载 | 这是外部服务不可用的提示，不影响任务、EP 和统计功能；应用会显示本地寄语。 |

## 从源码构建

### 环境要求

- Flutter SDK `3.12.2` 或更高版本。
- Dart SDK 版本由 `pubspec.yaml` 约束。
- Windows 10/11。
- Visual Studio 2019 或更高版本，并安装 **Desktop development with C++** 工作负载。
- Inno Setup 6（仅生成安装程序时需要）。

### 获取依赖并运行

```powershell
git clone https://github.com/Hongwei-name/Genie-Studio-App.git
cd Genie-Studio-App
flutter pub get
flutter run -d windows
```

### 构建 Windows Release

```powershell
flutter build windows --release
```

生成的程序位于：

```text
build\windows\x64\runner\Release\zero_k_genie.exe
```

### 生成安装程序

在 PowerShell 中从项目根目录运行：

```powershell
.\installer\Generate-Setup.ps1
```

脚本会自动递增补丁版本、构建 Windows Release，并调用 Inno Setup 生成 exe。生成结果位于 `installer_output` 目录。

## 项目故事：从重复点击到专属工具

我入职广西智数做智能标注员的第二天，就真切感受到了工作的桎梏。公司的标注平台功能格外简陋，很多重复繁琐的操作只能手动完成，耗时又费力，任凭我们怎么加快速度，工作效率始终提不上去。看着眼前单调重复的标注界面，我和同事不约而同动了心思：既然平台不够完善，那我们就自己动手，研发工具来适配工作、解放双手。

一切都是从零摸索开始。我们的第一个版本很粗糙，只是简单地检测页面元素、模拟点击。靠着这个小小的脚本，我们省去了大量机械点击的步骤，第一次真切感受到了自主优化带来的效率提升。但我们没有止步于此，发现漏洞和短板后，便继续熬夜打磨、迭代更新。

第二个版本，我们跳出了页面模拟操作的局限，开始摸索获取数据接口，通过拼接地址直接访问、抓取数据。这一次，工具的效率实现了质的飞跃，绕过了很多繁琐的页面流程，让标注工作的推进速度快了不止一倍。可我们依旧觉得不够完善，依旧在日复一日的工作之余，对着代码反复调试、优化细节。

几经打磨与重构，我们完成了第三次大版本更新，做出了专属的 Windows 爬虫软件。历经三次彻底迭代，从笨拙的模拟脚本，到高效的接口抓取，再到功能完整的桌面工具，这款软件的功能终于趋近完善。它适配了我们的标注工作场景，修复了已知问题，足以支撑我们高效、流畅地完成每日工作，正式投入生产使用。

可最遗憾的是，当我们倾尽心血打磨的工具终于圆满成型，我和并肩研发的伙伴们已经在办理离职手续了。

那些无数个加班调试的夜晚，那些反复推翻重来的迭代，那些为了优化一个细节反复钻研的时光，最终都停在了最好的一刻，也定格成了永远。从今往后，不会再有人为这款工具更新版本，不会再有人排查它的漏洞、优化它的功能。它会停留在最完整的模样，也可能随着平台变化慢慢被搁置、被遗忘。

我们亲手养大了适配这份工作的工具，却没能等到和它并肩深耕的日子。属于我们熬夜攻坚、自主破局的短暂时代，终究还是悄悄落幕了。

## 为什么不再更新

`3.0.7` 是当前研发团队能交付的最终版本，停止更新有明确的现实原因：

1. 原研发成员已经离开广西智数及对应的智能标注岗位，无法继续进行现场验证和需求迭代。
2. 工具依赖智元标注平台的登录流程、页面结构和接口行为；后续平台变化需要真实工作环境才能准确排查。
3. 继续维护需要持续的账号、网络和生产数据验证，而这些条件已经不再具备。
4. 因此项目选择在功能相对完整、已知问题完成修复的节点封存，而不是承诺一个无法保证的长期维护周期。

这不是一个仍在活跃开发的产品。Release 中的版本是历史工作成果的留存，使用者应自行评估兼容性、数据安全和平台规则，并为可能出现的故障准备人工处理方案。
